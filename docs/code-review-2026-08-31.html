Outside-eye review

VoxCodex Code Review

A terminal UI for an existing Audible library. The architecture is clean and the pure-logic layer is genuinely well tested — nearly every finding below lives at the thread-worker boundary or in the on-disk artifacts, the two areas the test suite does not reach.

commit 42cb8d5 version 0.3.0 reviewed 2026-08-31 tests 248 passing (~60s) scope ~1,900 LoC app / ~3,400 LoC test

How this was done. Two independent passes read every file in voxcodex/ plus the tests and docs/: a primary review and a second pass on a different model that verified claims against the installed textual 8.2.8 / audible 0.12.0 sources and against the live install under ~/.local/share/voxcodex/. Findings are merged and de-duplicated here, ordered by severity. IDs (C1, H3…) are just labels for reference in follow-up work.

Critical

C1

DEBUG logging writes full API response bodies to a world-readable, never-rotated file

voxcodex/app.py:57–68  ·  _setup_logging()

The logger tree turns on DEBUG for audible.client, which logs the entire response body of every request. That puts the content/{asin}/licenserequest response — carrying the encrypted AES voucher (license_response) and the signed CDN offline_url — in plaintext on disk, next to the complete library JSON and every annotations/lastpositions response. audible.auth at INFO logs the account username; voxcodex.auth._log_cvf_page logs every form input value on Amazon's identity-verification page (where hidden session tokens live).

On the live install the file is voxcodex.log, ~767 KB and growing, mode 0644 in a 0755 directory, with no RotatingFileHandler, no size cap, no off switch, and no mention in the README. The comment at app.py:64 — “Nothing here logs credentials in plaintext” — is false as written.

FixDefault the tree to WARNING; gate the audible.* DEBUG behind an explicit opt-in (VOXCODEX_DEBUG=1) that warns the log will contain response bodies. Use RotatingFileHandler(maxBytes=1_000_000, backupCount=2), create the file via os.open(…, 0o600), redact value in _log_cvf_page to a length indicator, and correct the comment.
C2

Three unrelated exclusive=True workers share the default group and cancel each other — and thread-worker cancellation does nothing

voxcodex/screens/library.py:176 (_fetch_library), :441 (_do_download), :495 (_open_player)

All three use @work(thread=True, exclusive=True) with no group=, so they land in Textual's "default" group on the same node. Starting any one cancels the others: pressing p cancels an in-flight download, d cancels a library refresh, r cancels both.

And the cancellation is cosmetic — a thread worker runs in an executor and completes regardless; Worker.cancel() only flags it. No worker here checks get_current_worker().is_cancelled. So pressing p twice quickly pushes two PlayerScreens and starts two mpv processes playing at once; two quick d presses run two downloads feeding interleaved updates into the single progress bar; r mid-download lets a “cancelled” worker still flip book.is_downloaded on a Book the refresh already replaced.

FixGive each worker its own group= ("library", "download", "player"). Then add a real if get_current_worker().is_cancelled: return at the top of every loop iteration and before every call_from_thread.
C3

Any uncaught exception in a thread worker tears down the whole app, and every worker has call_from_thread calls outside its try

voxcodex/screens/library.py:252, :456, :532  ·  player_screen.py:115

@work defaults to exit_on_error=True; on failure Textual calls _handle_exception and shows a traceback. The try blocks in these workers wrap only the network call — the call_from_thread(self._refresh_table) / _download_succeeded / _launch_player / _start_succeeded that follow are unguarded. If the screen was popped, query_one(…) raises NoMatches on the worker thread; if the app is shutting down, call_from_thread raises RuntimeError. Quitting while the background chapter fetch walks a large library (one HTTP call per book, minutes of runtime) reliably produces a crash dump instead of a clean exit.

FixPass exit_on_error=False and guard each callback with if not self.is_running or get_current_worker().is_cancelled: return, logging failures rather than raising.
C4

mpv is orphaned if the player screen closes while it is still starting — and --idle=yes means it never exits on its own

voxcodex/screens/player_screen.py:106–115  ·  services/player.py:55

self._player = player is assigned only after player.start(), which blocks up to 8 s inside _connect. During that whole window action_close and on_unmount see self._player is None and stop nothing. The worker then finishes, binds the player to a screen that no longer exists, and nobody ever calls stop(). Because the mpv command line carries --idle=yes, mpv does not exit at end-of-file either — the result is a permanently orphaned process holding the audio device, and the user's only recourse is pkill mpv.

FixAssign self._player = player before player.start(); have the worker re-check is_cancelled / is_running after start() and call stop() itself if the screen went away. Use --idle=once. In MpvPlayer.start(), wrap _connect() so a failed connect kills the subprocess it just spawned.

High

H1

The mpv IPC socket is a guessable path in shared /tmp with default permissions

voxcodex/services/player.py:38, :47–48

Path(tempfile.gettempdir()) / f"voxcodex-mpv-{id(self)}.sock". id(self) is a CPython address — low-entropy, repeatable across runs, reused after GC — never a secret. mpv creates the socket honoring the process umask, so it typically lands srwxr-xr-x, and mpv's JSON IPC includes the run command, which executes arbitrary programs: any local user who connects gets code execution as you. The if exists(): unlink() just above is a TOCTOU on a sticky directory, and the unlink is outside any try.

Fixself._dir = tempfile.mkdtemp(prefix="voxcodex-") (0700 by construction), socket inside it, shutil.rmtree(…, ignore_errors=True) in stop(). Removes the guessability, the exposure, and the TOCTOU together.
H2

Three independent Settings() instances each rewrite the whole file → silent lost updates

voxcodex/app.py:32  ·  screens/library.py:120  ·  screens/player_screen.py:86

Each Settings loads its own full copy of settings.json at construction, and every setter serializes that copy — no reload, no merge. The app's copy is loaded once at startup and never refreshed, so: cycle the sort in the library (its copy writes library_sort_key), then change the theme via the command palette → watch_theme writes the app's stale copy and silently reverts the sort. Same between library and player for playback_speed/volume. Compounding it, _fetch_library calls set_last_played_externally from a worker thread while the main thread may be mid-write — two Path.write_text calls on one file, non-atomic, can interleave and truncate (recovered as {}, i.e. all settings reset).

FixOne shared Settings owned by the app and passed down. Read-modify-write (or re-read before save) in every setter, guarded by a threading.Lock. Write atomically everywhere (settings.py:44, progress.py:63, library_cache.py:30): temp file + os.replace.
H3

Playback position is lost unless you exit the player with q/esc

voxcodex/screens/player_screen.py:261  ·  screens/library.py:550–563

dismiss(self._last_position_ms) fires only from action_close, and the _on_close callback is the only writer to ProgressStore and the only thing that pushes to Audible. Quit with ctrl+q (or close the terminal, or crash) and on_unmount stops mpv but dismiss never runs — the entire session's progress is discarded locally and remotely. There is no periodic checkpoint, so a 4-hour session that ends abnormally loses all 4 hours.

FixPersist position from _tick on a ~15 s interval when it has moved, and from on_unmount — making _on_close a final flush rather than the sole write path.
H4

Socket fd leak in _connect's retry loop; _sockfile is never closed

voxcodex/services/player.py:76–85, :164–167

The socket file usually appears before mpv is listening, so sock.connect() fails repeatedly — and the failed sock is never closed, leaking up to ~160 fds per start attempt over the 8 s / 0.05 s budget. Separately, stop() closes self._sock but nulls self._sockfile without closing it, skipping the final flush.

Fixsock.close() in the except branch (or contextlib.closing); self._sockfile.close() before self._sock.close() in stop().
H5

MpvError is not the only exception _command raises, and the unguarded paths crash the app

voxcodex/services/player.py:88–113  ·  screens/player_screen.py:159, :209–256

Socket I/O fails as BrokenPipeError / ConnectionResetError / socket.timeout — all OSError, not MpvError — so they escape get_property's except MpvError. if player.eof_reached: at _tick line 159 sits outside the tick's try, and every action_* calls _command with no guard at all: pressing space on a dead mpv crashes the app. Also, sock.makefile() combined with sock.settimeout() is documented-unsafe — on timeout the buffered object's state is left inconsistent, so later reads can mis-pair request/response.

FixCatch OSError in _command and re-raise as MpvError so the one exception type actually holds. Guard the action handlers. Replace makefile with manual sendall/recv buffering, or drop the socket timeout for a watchdog.
H6

Blocking mpv IPC on the Textual event loop

voxcodex/screens/player_screen.py:128–174  ·  services/player.py:156–180

_tick runs on the event loop once a second and does four synchronous IPC round-trips (time-pos, duration, pause, eof-reached), each with a 5 s timeout — a stalled mpv freezes the whole TUI for up to 20 s per tick. action_close → stop() issues a quit (2 s timeout) plus proc.wait(timeout=3.0) on the loop, so q can hang the UI for 5 s. Every action_* is a blocking round-trip too.

FixIdiomatically: one reader thread using mpv observe_property, pushing changes in via post_message. Failing that, move _tick's reads into a @work(thread=True, group="poll") worker, make stop() fire-and-forget, and cut the property timeout to ~0.5 s.
H7

_blocking_prompt can hang the process at exit

voxcodex/screens/login.py:250–266

event.wait() has no timeout and no cancellation. It runs on a non-daemon thread from asyncio's default executor, which asyncio.run awaits on teardown. If the user hits ctrl+q / ctrl+c while an OTP or CAPTCHA prompt is open, the modal is torn down without _done ever firing, event.wait() blocks forever, and the process hangs on exit.

Fixevent.wait(timeout=…) in a loop that also checks a screen-level “shutting down” flag set from on_unmount; return "" when abandoned so the login flow fails cleanly.
H8

query_one is evaluated on the worker thread during download, once per 256 KB chunk

voxcodex/screens/library.py:443–449

self.app.call_from_thread(self.query_one("#download-progress", ProgressBar).update, …) — the query_one runs in the worker thread, a DOM traversal off the event loop, exactly what call_from_thread's docs warn against. If the screen was popped it raises NoMatches on the worker thread (crash, per C3) and leaves a .part file. It also fires once per chunk and blocks on the result — a ~1 GB download is thousands of synchronous event-loop round-trips, each stalling the download.

FixResolve the widget inside a main-thread callback wrapped in try/except NoMatches, and throttle to ~4 updates/sec.
H9

Login workers are not exclusive; a double-submit permanently corrupts the diagnostics monkeypatch and leaks an API client

voxcodex/screens/login.py:160, :185, :221  ·  services/auth.py:71–114

@work(thread=True) with no exclusive, and nothing debounces the button beyond a CSS display:none. Two concurrent _do_login calls both enter _login_flow_diagnostics(), which swaps five functions on audible.login; the second context manager captures the first one's wrappers as its “originals”, so the outer finally restores a wrapper — audible.login stays monkeypatched for the life of the process. Both logins also reach app.on_authenticated, which overwrites self.api; the first AudibleAPI's httpx client is never closed.

Fixexclusive=True, group="login" on all three, an explicit if self.has_class("busy"): return guard, and a reentrancy guard (module lock) in _login_flow_diagnostics.
H10

textual>=0.60.0 is not a satisfiable floor

pyproject.toml:20–25

App.theme / App.available_themes (app.py:34–41) arrived with Textual's theme system in ~0.86; installing against the declared floor throws AttributeError at startup. audible>=0.10.0 is likewise optimistic given the code reaches into audible.aescipher.decrypt_voucher_from_licenserequest, audible.client.raise_for_status, and monkeypatches five private audible.login functions. No dependency has an upper bound.

Fixtextual>=0.86,<9, audible>=0.10,<0.13. Add a smoke test that imports the five audible.login names the diagnostics patch depends on, so a bad bump fails in CI, not at a user's first login.

Medium

M1

The background chapter fetch is O(N²) in table rebuilds and N in HTTP calls

voxcodex/screens/library.py:235–252, :263–289

Per book: one HTTP call, then call_from_thread(self._refresh_table), which clears and re-adds every row and linear-scans _filtered to restore the cursor. A 500-title library is 500 sequential network calls and ~250k add_row calls, every session (the cache is in-memory only). _populate_offline runs it too — so when the network is down, every call fails slowly against the 30 s client timeout.

FixBatch the refresh (every ~25 books or a 500 ms coalescing timer); update only the changed cell via table.update_cell; check is_cancelled; skip entirely in the offline branch; persist chapter totals to disk (they never change) and recompute only the current-chapter number locally.
M2

Insecure default permissions on everything except auth.json

voxcodex/config.py:22–25  ·  services/download.py:63–80  ·  services/auth.py:150–161

On the live install: dirs 0755; settings.json, progress_cache.json, library_cache.json (your full purchase history), voxcodex.log, and *.voucher.json (the AES key + iv) all 0644. auth.save chmods correctly but after to_file returns (a readable window), and the encrypted branch never chmods at all.

Fixmkdir(mode=0o700) in ensure_dirs; a shared _write_private() helper using os.open(…, O_WRONLY|O_CREAT|O_TRUNC, 0o600) for settings/progress/cache/voucher/log; pre-create the auth file at 0600 in both branches.
M3

.part files are never cleaned up; a truncated download becomes a “downloaded” book

voxcodex/services/download.py:37–60

Any exception between open(tmp_path, "wb") and tmp_path.replace(audio_path) leaves the partial file forever — and test_download.py:169 doesn't cover this because its simulated failure is raised before the file is opened. There's also no check that downloaded == total before the rename, so a mid-stream connection drop produces a corrupt .aaxc that is_downloaded() happily reports as present, failing later with a confusing playback error. Two workers on the same ASIN (reachable per C2) interleave into one file.

Fixtry/except: tmp_path.unlink(missing_ok=True); raise. Verify the byte count against content-length before replace(). Write the voucher before the rename. Sweep stale *.part at startup.
M4

Library pagination can truncate silently or loop forever

voxcodex/services/api.py:113–128

if len(items) < num_results: break assumes the server honors num_results=1000 exactly. If Audible ever caps lower, the loop stops after page 1 and returns a truncated library — which then overwrites the offline cache at :192. If a full page is always returned, while True never terminates.

Fixif not items: break, plus a hard if page > 100: break, plus a log line when the page size comes back unexpected.
M5

progress_ms is monotonically non-decreasing and can never be corrected

voxcodex/screens/library.py:217

book.progress_ms = max(book.progress_ms, local_ms, remote_ms). Restart a book from chapter 1 on your phone and VoxCodex keeps showing — and resuming at — the old, higher position forever. Only the in-app _on_close write can ever lower it.

FixTrust the newest by timestamp, not the largest by value. ProgressStore already records updated_at and the remote annotation carries last_updated — compare those.
M6

Sync failures are completely invisible to the user

voxcodex/services/progress.py:169–205  ·  screens/library.py:565–571

push_position / push_finished swallow every exception into logger.debug, and their callers discard the returned bool. An expired token or revoked device registration looks exactly like success. Given C1 makes the log the only diagnostic — and undocumented — a user has no way to notice their progress stopped syncing. The best-effort semantics are right; the silence is not.

FixSurface a one-line status on failure (“Progress saved locally; Audible sync failed”). MessageModal (currently dead code, see L1) is the natural home.
M7

except Exception is too broad in the selection, chapter, and license paths

voxcodex/screens/library.py:247, :295–298, :519

coordinate_to_cell_key raises CellDoesNotExist for an out-of-range cursor — that's the case to handle; catching everything means a genuine bug shows up as “pressing d silently does nothing.” The chapter/license catches similarly turn an API failure into “this book just has no chapters,” hiding real breakage.

FixNarrow to CellDoesNotExist and to httpx.HTTPError / audible.exceptions.* respectively; let the rest propagate to the worker error handler.
M8

DRM key, IV, and signed URL are passed on mpv's command line

voxcodex/services/player.py:50–59

--demuxer-lavf-o=audible_key=…,audible_iv=… plus the URL. /proc/<pid>/cmdline is world-readable, so any local user can read the AES key, the IV, and the CDN URL for as long as mpv runs. Same underlying exposure as M2's 0644 voucher, but a second copy and a cheap fix.

FixWrite the options to a 0600 file in the private temp dir (H1) and pass --include=, or start mpv idle and loadfile over IPC with the options as a per-file option dict.
M9

No linter, formatter, or type checker — despite the code being written for them

pyproject.toml  ·  .github/workflows/tests.yml

The source carries eleven # noqa: BLE001 markers (ruff codes) and there's a .ruff_cache/ in the worktree — ruff has been run ad hoc but is not pinned, configured, or enforced. Everything is fully annotated, but there's no mypy, no py.typed, and CI runs pytest only. mypy would immediately flag self._sockfile = None typed as None (then reassigned), the tuple[str, dict] | tuple[None, None] return in progress.py that callers can't narrow, and missing return annotations. The CI matrix is 3.10, 3.12, 3.13 — 3.11 is missing though pyproject claims it. Version is duplicated in pyproject.toml and __init__.py.

FixAdd [tool.ruff] (line-length 100; E,F,B,BLE,SIM,UP), [tool.mypy] strict for voxcodex/, a dev extra, py.typed, and lint + typecheck CI jobs. Add 3.11. Make the version dynamic.
M10

The risky concurrency paths have no test coverage — and there is no test_auth.py at all

tests/

The 248 tests are strong on parsing and screen keybindings (real Pilot keypresses, not action_* calls) and correctly sandbox user data. But nothing covers: worker cancellation / group collisions (C2); screen-popped-during-worker (C3, C4); MpvPlayer's socket lifecycle beyond the not-connected branches (H4, H5); a mid-stream download failure (M3); multiple Settings clobbering each other (H2, a two-line test). And services/auth.py — the monkeypatch/restore, _log_cvf_page, save()'s chmod, among the most fragile and security-relevant code here — is entirely untested.

FixAdd tests/test_auth.py. Add pilot tests that block a fake API on an Event, fire two actions, and assert one screen / one stop(). Stand up a fake AF_UNIX server in tmp_path to exercise the real socket code.

Low

  • L1 · modals.py:77 — MessageModal is dead code. Never instantiated; login.py:14 imports it unused. It is tested, so the tests keep dead code alive. Use it for the M6 sync-failure notice, or delete both.
  • L2 · api.py:167 — License.last_position_ms is never read. The most authoritative resume position available — fetched fresh with the license at the moment of playback — is discarded in favor of the possibly-stale book.progress_ms. Use it in _launch_player or drop the field.
  • L3 · library.py:570 — set_finished(asin, False) is unreachable. The API and push_finished support un-finishing, but the call site hardcodes True and there's no UI to undo a mis-detected end (0.98 threshold on a book with long credits). Permanent from inside VoxCodex.
  • L4 · app.py:47 — on_authenticated shadows Textual's handler-naming convention. It's a plain method called directly from login.py:274; a future Authenticated(Message) would silently collide. Rename to set_authenticator(), or make it a real Message.
  • L5 · library.py:331 — Search re-sorts and rebuilds the whole table on every keystroke. Noticeable lag on a large library. Debounce with a cancelled-and-reset set_timer(0.15, …).
  • L6 · settings.py:32, progress.py:51 — Settings(path=config.SETTINGS_FILE) binds the default at import. Tests can't monkeypatch config and work around it by patching the class. Take path: Path | None = None and resolve inside __init__.
  • L7 · library.py:283 — add_row(key=book.asin) can raise DuplicateKey. _book_from_item defaults a missing ASIN to "", so two malformed items crash the render. Skip ASIN-less items at parse time.
  • L8 · login.py:138 — _reset pops its own screen then pushes a replacement from inside that screen's button handler. self.app.switch_screen(…) is the single idiomatic operation.
  • L9 · library.py:385 vs :68 — “Finished” is defined two ways: the filter uses progress_pct >= 100, _reached_end uses >= 98%. A never-played-in-app book at 99% is neither finished nor in-progress. Use _FINISHED_FRACTION in both.
  • L10 · app.py:33–41 — watch_theme writes to disk during __init__. Setting self.theme fires the watcher, so every launch does a settings write before the UI renders. Guard with a self._loading_theme flag.
  • L11 · login.py:233 — import webbrowser inside a function. Move to module scope.
  • L12 · api.py:133, :253 — quality silently coerces typos. "High" if quality != "normal" else "Normal" maps any bad value to High. Validate against ("high", "normal").
  • L13 · downloads/ — ~1.5 GB of downloads with no UI affordance: no total-size display, no bulk cleanup, no “delete finished,” and x deletes one at a time from a table that doesn't show sizes.

Nits

  • N1 — scratch/whispersync/probe.py is committed and hardcodes sys.path.insert(0, "/home/jake/Work/…") (a path absent from any clone), names the developer's marketplace, and references two titles from their personal library. It's excluded from the wheel but not the public repo.
  • N2 — scratch-whispersync/ (byte-identical duplicate) and empty scratch-ws/ are untracked leftovers, and .gitignore covers neither, nor .claude/. Add scratch*/ and .claude/; move the probe under tools/.
  • N3 — docs/whispersync-research.md contains a live account identifier (guid="CR!…:116727321") captured from a real request, plus ASINs/positions from the developer's library. Redact the guid at least — the research value doesn't need the real value.
  • N4 — README documents a keybinding that doesn't exist: the library table lists q → Quit, but LibraryScreen.BINDINGS has no q (only ctrl+q, from the app). This interacts with H3 — on the player screen q saves position and ctrl+q doesn't, so the docs point at the lossy path.
  • N5 — README's “Local data” never mentions voxcodex.log, the largest and most sensitive artifact the app produces (C1).
  • N6 — asyncio_mode = "auto" without asyncio_default_fixture_loop_scope emits a PytestDeprecationWarning on pytest-asyncio ≥ 0.24 (which the test extra allows). Set it explicitly.
  • N7 — _current_chapter_index reads a 1 Hz-stale position. Pressing n right after a seek uses the pre-seek chapter. Read player.position_seconds in the action instead of _last_position_ms.
  • N8 — The sleep timer expiring gives no feedback beyond the readout vanishing; eof_reached sets the state text to “Finished” but does nothing else — no auto-close, no finish mark, no stop to the 1 Hz poll.

What's already solid

Deliberately not flagged — this is real quality worth preserving:

  • The Book model and its display properties are clean and thoroughly tested; the chapter_current is None vs 0 distinction is a subtle case handled correctly and covered.
  • library_cache.load()'s exception tuple correctly absorbs schema drift after an app update.
  • progress.py's annotation parsing is careful, and its module docstring documenting the previously-silent read bug is exemplary.
  • _book_from_item's or {} / or [] defensiveness against Audible's inconsistent response shapes is right.
  • subprocess.Popen is called with a list and no shell; push_last_position refuses to fire without a real acr and explains why.
  • The priority=True binding on up with its comment is the correct solution to that focus problem.
  • Tests drive real Textual pilots pressing real keys rather than calling action_* — the right call, and rare.
  • Comment density is high but almost all of it is load-bearing “why,” not “what.”

Suggested order of work

  1. C1 — log redaction, rotation, 0600. Smallest diff, largest risk reduction, and it's leaking on your own machine right now.
  2. C2 + C3 together. Distinct group= per worker, an is_cancelled check atop each callback, exit_on_error=False. One focused pass over library.py that removes most of the crash surface.
  3. C4 + H1 + H4 + H5 — an MpvPlayer lifecycle rewrite. Private temp dir, close every socket, OSError→MpvError, assign _player before start(), --idle=once. Ship it with the fake-socket-server tests from M10.
  4. H2 + H3 — the two silent data-loss bugs. One shared Settings, atomic writes everywhere, periodic position checkpointing.
  5. M9 — wire up ruff + mypy in CI before the codebase grows further. Several Low items fall out for free.
